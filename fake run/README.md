## Race mode (main project)

The fixed-path driver is the main race stack. It publishes `/race/cmd`; the
command mux is the only owner of `/cmd`, so the fruit-fly side-project can never
fight it.

```sh
source sim/install/setup.bash
ros2 launch eufs_sim2 eufs_sim2.launch.py
ros2 service call /set_mission eufs_msgs/srv/SetMission "{mission: 4}"
ros2 service call /go std_srvs/srv/Trigger "{}"

bash "fake run/start_race_mode.sh"
```

`start_race_mode.sh` runs the scenery, the race-mode mux and the driver
together. The explicit three-command version is:

```sh
python3 "fake run/track_scenery.py"    # road, barriers, real cones, trees
python3 "fake run/cmd_mux.py"          # race mode is the default
python3 "fake run/fixed_path_driver.py"
```

### Inside the container (one command)

Run this in a terminal **inside the dev container** (from any directory):

```sh
bash "fake run/start_race.sh"
```

It sources ROS and the simulator, starts `eufs_sim2` if it is not already
running, waits for `/odom`, calls `/set_mission {mission: 4}` + `/go`, then runs
the race stack (`scenery + trail + camera + mux + driver`). Ctrl-C stops the
race stack but leaves the simulator running.

Options:

```sh
bash "fake run/start_race.sh" --detach     # keep running after the terminal closes
bash "fake run/start_race.sh" --foxglove   # also start foxglove_bridge :8765
bash "fake run/start_race.sh" --stop       # stop the race stack, leave the sim
RACE_CAMERA=0 bash "fake run/start_race.sh"  # skip the OpenCV camera

# use a track generated by track_editor.py
bash "fake run/start_race.sh" --detach \
  --track "fake run/track_editor.csv" \
  --centerline "fake run/centerline_editor.csv"
```

`--detach` is the safe choice when you want to close the terminal and keep the
car driving. `--track` loads the CSV into `eufs_sim2`, resets the car to the
start, and passes the same files to the scenery, camera, trail and driver.

Stop explicitly:

```sh
bash "fake run/start_race.sh" --stop
# or:
bash "fake run/stop_race_mode.sh"
```

`start_race_mode.sh` refuses to start if a `fixed_path_driver.py` or `cmd_mux.py`
is already running, so a second stack cannot fight the first.

### Track editor (draw / auto-place cones)

Run the GUI on Windows with the portable Python (tkinter is included):

```powershell
C:\Users\V9\flyscreen-portable\flyscreen-portable\runtime\python\python.exe `
  "C:\Users\V9\autonomous-driving-crash-course\fake run\track_editor.py"
```

Two modes:

1. **Draw centreline** — left-click points. Set half-width and cone spacing,
   press **Auto cones**: blue on the left, yellow on the right, orange start
   cones. **Reverse centreline** swaps the sides if the loop direction is wrong.
2. **Place cones** — choose Blue/Yellow/Orange, left-click to add, right-click
   to delete. **Centreline from cones** derives an ordered centreline from the
   blue/yellow pairs.

Middle-drag pans, the wheel zooms, `Ctrl-Z` undoes, `Ctrl-S` saves to
`fake run/track_editor.csv` + `fake run/centerline_editor.csv`. Trees are
previewed as green circles; the real tree scenery is generated automatically by
`track_scenery.py` / `track_camera.py` from the saved centreline.

Headless auto-generation from a centreline:

```powershell
...\python.exe "fake run\track_editor.py" --auto `
  --out "fake run\track_editor.csv" --center-out "fake run\centerline_editor.csv"
```

The editor writes LF CSV (`car_start,0,0,0`); the simulator loads it with an
identity start transform, so `/map`, `/track/scenery` and the driver all agree.

### Foxglove: what to subscribe to

Start the bridge (or use `bash "fake run/start_race.sh" --foxglove`):

```sh
ros2 run foxglove_bridge foxglove_bridge --ros-args -p port:=8765
```

Connect Foxglove to `ws://localhost:8765`. Quick setup: **Layouts → Import
layout** and choose [`foxglove_race_layout.json`](foxglove_race_layout.json).
It creates a 3D panel and an Image panel already pointed at `/race/camera` /
`/race/camera_info`. If you prefer manual panels: **+ Add panel → 3D**, set the
fixed frame to `map`, tick `/track/scenery` and `/race/trail`; then **+ Add panel
→ Image**, set **Image topic** to `/race/camera` and **CameraInfo topic** to
`/race/camera_info`.

If the Image panel is missing, it will not appear automatically — you must add
an Image panel yourself. The image topic is live at ~8–12 Hz.

Enable these topics in the 3D panel:

| Topic | Type | What you should see |
|---|---|---|
| `/track/scenery` | MarkerArray | asphalt road, white edges, barriers, real cone meshes, trees, grass, **red centreline** |
| `/centerline_markers` | MarkerArray | the same centreline on its own topic (run `publish_centerline_markers.py`) |
| `/race/trail` | MarkerArray | **green previous trail**, reset at every start-line crossing |
| `/robot_description` | URDF | the car model; tick it in the 3D panel to see the car move |
| `/race/camera` | Image (`bgr8`) | realistic OpenCV first-person camera; frame `base_footprint` |
| `/race/camera_info` | CameraInfo | camera intrinsics; select it in the Image panel to silence “No CameraInfo topic found” |
| `/race/cone_hits` | Int32 | cone hits this lap |
| `/race/penalty_s` | Float32 | time penalty this lap |
| `/race/lap` | Int32 | completed laps |

Inside `/track/scenery`, the marker namespaces are
`scenery/road`, `scenery/edge_left`, `scenery/edge_right`,
`scenery/centerline`, `scenery/barrier_left`, `scenery/barrier_right`,
`scenery/cone_blue`, `scenery/cone_yellow`, `scenery/cone_orange`,
`scenery/cone_band`, `scenery/cone_base`, `scenery/tree_trunk`,
`scenery/tree_canopy`, and `scenery/sky` (if enabled). Expand the topic in the
3D panel to toggle individual namespaces.

The default EUFS Foxglove extension also draws cones as cylinders. Our meshes
are larger and cover them; hide the extension's cone display if you want only
the realistic cones. If `/track/scenery` does not appear, check:

```sh
ros2 topic hz /track/scenery     # should be ~0.1 Hz (latched) or one message
ros2 node list | grep track_scenery
ros2 topic list | grep -E 'track|race'
```

The scenery is latched and republished every 10 s, so a 3D panel that connects
later will still receive it. New topics are **not auto-enabled** in an existing
3D panel — you must tick them in the panel's topic list.

For `/race/camera`, set the Image panel's **CameraInfo** topic to
`/race/camera_info`. The camera frame is `base_footprint`, which exists in the
simulator TF tree, so there is no “missing transform to map” warning. The
`/race/trail` marker is deleted and restarted whenever the car crosses the
start line (each lap).

The scenery is static; to **see the car move**, tick `/robot_description` in
the 3D panel (car model) and/or enable `/race/trail` (growing green line), and
set the 3D **Follow frame** to `base_footprint`. The `/odom` position is moving
even if the track itself does not change.

There are two camera views:

- **`/race/camera`** — the realistic first-person scene from
  `track_camera.py`; this is the one to put in the Image panel. It is started by
  `start_race.sh`.
- **`/camera/synthetic`** — the old detection-only view from
  `camera_opencv_viewer.py` (run with `python3`, not by executing the `.py`
  directly). It draws the `/camera/cones` detections, not the full scene.

The “limited FOV highlight while approaching” is the 3D panel’s cone detection
range, not the camera image. The camera image is a **separate Image panel**.

### Why `/map` and `/track/scenery` now agree

`eufs_sim2` applies the `car_start` row to the track. The FSUK file contains:

```text
car_start,4.0,0.0,201.0,0.0,0.0,0.0
```

so the sim translates by `(-4, 0)` and rotates by `-201 rad` (≈ −0.062 rad).
`/map` is in that car-start frame. Our `Track` class now applies the same
transform to both the cones and `fixed_path_centerline.csv`, so the scenery,
camera, trail and driver all match `/map`. The editor writes
`car_start,0.0,0.0,0.0` (identity), so a custom track is already in the map
frame.

### Diagnostics

```sh
# Is the midpoint actually wrong? (raw CSV, before the start transform)
python3 "fake run/audit_centerline.py"

# What is /map in? Compare /map with the CSV / scenery.
python3 "fake run/map_probe.py" --seconds 5

# Live trail + CSV with s / lateral / half_width / limit
python3 "fake run/trail_recorder.py"

# Save one frame of the OpenCV camera for inspection
python3 "fake run/camera_snapshot.py"   # -> fake run/out/camera.png

# Headless auto track from a centreline
python3 "fake run/track_editor.py" --auto
```

`start_race_mode.sh` starts the scenery, trail recorder, camera and mux. If you
run only `fixed_path_driver.py`, those visual topics will not exist — that is
the usual reason Foxglove looks unchanged.

`audit_centerline.py` on the FSUK 2023 track reports:

```text
midpoint deviation: mean 0.137 m, median 0.119 m, max 0.289 m
blue-left / yellow-right anomalies: 0 of 98
```

So the midpoint is not the main cause. The driver now checks the car's **four
corners** (`car_length 2.4 m`, `car_half_width 0.75 m`) against the local wall
limit, not just the centre; that catches the front/rear corner clipping that a
centre-only check misses. The trail CSV
(`fake run/out/race_trail_*.csv`) records `lap`, `s`, `lateral`, `half_width`
and `limit` so you can see exactly where a corner left the corridor. The green
`/race/trail` marker is cleared at each start-line crossing and starts again.

Diagnostics: `/race/cone_hits`, `/race/penalty_s`, `/race/lap`.
The driver now keeps the whole car inside the cone line
(`half_width - car_half_width - wall_margin`), uses an adaptive lookahead,
Stanley correction and a heading-based wall prediction. Tune with
`-p target_speed:=... -p lookahead:=... -p car_half_width:=...`.

With the mux running, `fixed_path_driver.py` must use its default
`/race/cmd`. For the old standalone behaviour:
`python3 "fake run/fixed_path_driver.py" --ros-args -p cmd_topic:=/cmd`.

## Fruit-fly fun mode (separate)

This is a team fun activity, not the race controller. **Do not run
`fixed_path_driver.py`** at the same time. Start the mux in fly mode and run the
fly bridge (it publishes `/fly/cmd`):

```sh
python3 "fake run/cmd_mux.py" --ros-args -p mode:=fly
ros2 launch fly_bridge fly_bridge.launch.py
```

The default mux mode is `race`, so starting the fly by accident cannot move the
car. See `fruitfly/README.md` for the flyscreen, relay and Foxglove panels.
